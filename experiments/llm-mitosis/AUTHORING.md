# Mitosis + Tailwind + Headless Component Authoring Guide

This guide documents the architecture, patterns, and best practices for authoring cross-framework UI components using **Mitosis**, **Tailwind CSS**, and **Headless State Logic**, starting from raw Figma tokens and component payloads.

---

## 1. Architectural Overview

The goal of this architecture is **Single-Source Component Authoring**: writing a component once in Mitosis JSX (`.lite.tsx`), styled with Tailwind utility classes and design tokens, and compiling it deterministically into production-ready components for multiple target frameworks:

```
┌─────────────────────────────────┐
│   Figma Snapshot & Tokens       │ (.cache/figma, reference/tokens.json)
└────────────────┬────────────────┘
                 │ prepare-context.cjs
                 ▼
┌─────────────────────────────────┐
│   Normalized Context            │ (context/*.json, context/tokens.css)
└────────────────┬────────────────┘
                 │ LLM / Human Authoring
                 ▼
┌─────────────────────────────────┐
│   Mitosis Source (.lite.tsx)    │ (source/*.lite.tsx)
│   + Headless State & Logic      │
│   + Tailwind CSS Classes        │
└────────────────┬────────────────┘
                 │ compile.cjs (@builder.io/mitosis)
    ┌────────────┼────────────┬────────────┐
    ▼            ▼            ▼            ▼
┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
│ React  │   │ Vue 3  │   │ Vue 2  │   │ Svelte │
│ (.tsx) │   │ (.vue) │   │ (.vue) │   │(.svelte│
└────────┘   └────────┘   └────────┘   └────────┘
```

## 2. LLM Authoring from Figma Raw Payloads

When generating Mitosis components from design snapshots, the authoring process consumes normalized context generated by `prepare-context.cjs`:
- `context/<ComponentName>.json`: Cleaned Figma node payload containing Auto Layout parameters, bounding geometry, variants, and component property definitions.
- `context/tokens.json`: Canonical design tokens (colors, typography, spacing, elevations).
- `context/tokens.css`: CSS custom properties projected from the token dictionary.

### Reading Figma Auto Layout

Figma Auto Layout maps directly to CSS Flexbox and Grid constructs:

| Figma Property | Figma Values | Tailwind Utility Mapping |
| :--- | :--- | :--- |
| `layoutMode` | `HORIZONTAL` | `flex flex-row` |
| `layoutMode` | `VERTICAL` | `flex flex-col` |
| `primaryAxisAlignItems` | `MIN`, `CENTER`, `MAX`, `SPACE_BETWEEN` | `justify-start`, `justify-center`, `justify-end`, `justify-between` |
| `counterAxisAlignItems` | `MIN`, `CENTER`, `MAX`, `BASELINE` | `items-start`, `items-center`, `items-end`, `items-baseline` |
| `itemSpacing` | Numeric (e.g. `8`, `12`, `16`) | `gap-2`, `gap-3`, `gap-4` |
| `paddingLeft/Right/Top/Bottom` | Numeric (e.g. `16`, `24`) | `px-4 py-6` or individual `pl-*`, `pr-*`, etc. |
| `layoutSizingHorizontal` | `FIXED`, `HUG`, `FILL` | `w-[Xpx]`, `w-fit`, `w-full` / `flex-1` |
| `layoutSizingVertical` | `FIXED`, `HUG`, `FILL` | `h-[Ypx]`, `h-fit`, `h-full` / `self-stretch` |

### Reading Geometry, Visuals, and Corner Radii

- **Corner Radius**: `cornerRadius: 4` -> `rounded`, `8` -> `rounded-lg`, `12` -> `rounded-xl`, `9999` -> `rounded-full`.
- **Borders & Strokes**: `strokes`, `strokeWeight` -> `border border-gray-200` or custom CSS variable borders.
- **Fills & Colors**: Resolve fill hex or rgba values against `context/tokens.css` or default to semantic Tailwind palette (`text-gray-900`, `bg-blue-600`, `bg-white`).
- **Typography**: Figma font style objects (`fontSize`, `fontWeight`, `lineHeightPx`) map to `text-xs font-semibold leading-relaxed`, etc.

## 3. Mitosis `.lite.tsx` Authoring Rules

Mitosis source files (`.lite.tsx`) must strictly obey Mitosis JSX syntax to compile across all targets.

### Rules & Invariants

1. **State with `useStore`**:
   - Store reactive state and computed properties using `useStore({ ... })`.
   - Computed properties must be written as ES6 getters (`get myProperty() { return ...; }`).
   - Mutation methods must be defined inside `useStore`.
2. **Default Props with `useDefaultProps`**:
   - Declare default prop values at the top of the component using `useDefaultProps({ ... })`.
3. **Control Flow Primitives**:
   - Use `<Show when={condition} else={<Fallback />}>` instead of ternary operators or `&&` when rendering blocks.
   - Use `<For each={state.items}>{(item, index) => <div key={item.id}>...</div>}</For>` for iteration.
4. **Strict Cross-Framework Prohibitions**:
   - **NO React Hooks in `.lite.tsx`**: Do not use `useState`, `useEffect`, `useMemo`, or `useCallback`. Mitosis manages component lifecycle and transforms `useStore` into target-native mechanisms (React `useState`, Vue `reactive`/`computed`, Svelte reactive declarations).
   - **NO Target Directives**: Do not use `v-if`, `v-for`, `{#if}`, or `ngIf`.
   - **NO DOM Mutations**: Avoid direct `document.querySelector` or raw DOM mutations inside component render.
   - **NO Target Event Object Leaks**: Callback props must pass extracted values or clean parameters rather than raw target-specific DOM events (e.g. `onCheckedChange(bool)` instead of `onChange(e)`).
5. **Single Export**:
   - Always export default the component function.

### Canonical Mitosis Component Template

```tsx
import { Show, useDefaultProps, useStore } from '@builder.io/mitosis';

export interface MyComponentProps {
  label: string;
  variant?: 'primary' | 'secondary';
  disabled?: boolean;
  onAction?: (label: string) => void;
}

export default function MyComponent(props: MyComponentProps) {
  useDefaultProps({
    variant: 'primary',
    disabled: false,
  });

  const state = useStore({
    get containerClasses() {
      const base = 'inline-flex items-center px-4 py-2 rounded-lg font-medium transition-colors';
      const variantClass = props.variant === 'secondary'
        ? 'bg-gray-100 text-gray-900 hover:bg-gray-200'
        : 'bg-blue-600 text-white hover:bg-blue-700';
      const disabledClass = props.disabled ? 'opacity-50 pointer-events-none' : 'cursor-pointer';
      return [base, variantClass, disabledClass].join(' ');
    },
    handleClick() {
      if (!props.disabled && props.onAction) {
        props.onAction(props.label);
      }
    },
  });

  return (
    <button
      type="button"
      class={state.containerClasses}
      disabled={props.disabled}
      onClick={() => state.handleClick()}
    >
      <span>{props.label}</span>
    </button>
  );
}
```

## 4. Headless Component Patterns (Table & Chart)

For non-trivial UI components like data tables and charts, presentation markup must be separated from pure headless calculation logic.

### Headless Table Pattern (`Table.lite.tsx`)

The Table component encapsulates data validation, selection mathematics, and empty-state branching while outputting accessible, semantic markup.

- **State Validation Invariants**:
  - The computed getter `state.invalid` validates columns (unique keys, present labels), rows (unique ids, valid cell records), and required callbacks before rendering.
- **Selection Computation**:
  - `state.selectedCount`: Number of selected rows.
  - `state.allSelected`: Boolean indicating whether every row in the current dataset is selected.
  - `state.isIndeterminate`: Boolean indicating whether some, but not all, rows are selected.
  - `state.isSelected(id)`: Checks inclusion in `props.selectedIds`.
- **Pure Interaction Handlers**:
  - `state.handleSelectAll(checked)`: Emits all row IDs or an empty array.
  - `state.handleRowSelect(id, checked)`: Emits updated array of IDs without mutating props.
- **Accessible HTML5 Markup**:
  - Semantic `<table>`, `<caption class="sr-only">`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>`.
  - Checkbox controls with `aria-label` identifying each target row.

### Headless Chart Pattern (`Chart.lite.tsx`)

The Chart component computes SVG geometry analytically inside Mitosis store getters without relying on heavy third-party visualization libraries.

- **Bounds & Dynamic Scaling**:
  - `state.bounds` inspects values to determine `{ min, max, range, zeroY }`.
  - Handles edge cases defensively:
    - **Zero values**: `min: -10, max: 10` to avoid division by zero.
    - **Single value**: Scaled to provide visual headroom (`max * 1.25`).
    - **All negative values**: `max` pinned to 0, `min` scaled with 15% padding.
    - **Clamped baseline (`zeroY`)**: Calculated via `24 + 180 * ((maxVal - 0) / range)` and clamped between 24 and 204 to ensure axes and bars never render outside SVG viewport bounds.
- **Defending Against NaN & Infinity**:
  - Bar coordinates: `x = 40 + index * step`, `y = Math.min(zeroY, pointY)`, `height = Math.abs(pointY - zeroY)`.
  - All calculated SVG attributes (`viewBox`, `rect x/y/width/height`, `polyline points`, `circle cx/cy`) are guaranteed finite.
- **Companion Accessible Table**:
  - Screen readers cannot interpret raw SVG shapes. The component renders an accessible `<table>` alongside the SVG containing all labels and formatted values.
- **Defensive Error Fallbacks**:
  - `state.isInvalidVariant`: Renders an alert with `role="alert"` when unsupported variants are provided.
  - `state.isEmpty`: Renders an empty state placeholder.
  - `state.hasInvalidData`: Prevents SVG rendering when data points contain non-finite numbers.

## 5. Cross-Target Compilation Considerations

Mitosis compiles `.lite.tsx` files to target frameworks via `compile.cjs`. Each target framework has distinct compilation requirements:

### React (`.tsx`)
- Generated with `mitosis.componentToReact({ typescript: true })`.
- Compiles into standard React functional components with `useState` and typed interfaces.
- JSX attributes use camelCase (`className`, `viewBox`, `strokeWidth`, `strokeLinecap`).

### Vue 3 (`.vue` Composition API)
- Generated with `mitosis.componentToVue({ api: 'composition', typescript: true })`.
- Outputs Single File Components (`<template>`, `<script setup lang="ts">`, `<style>`).
- Getters in `useStore` compile into Vue 3 `computed(...)` properties.
- State properties compile into Vue 3 `ref(...)` or `reactive(...)`.

### Vue 2 (`.vue` Options API)
- Generated with `mitosis.componentToVue({ api: 'options', defineComponent: false })`.
- Crucial configuration:
  - `api: 'options'`: Uses the Vue 2 Options API (`data()`, `computed:`, `methods:`).
  - `defineComponent: false`: Avoids importing `@vue/composition-api` shim which may not be present in pure Vue 2 environments.
- Method names and computed properties must not collide with prop names.

### Svelte (`.svelte`)
- Generated with `mitosis.componentToSvelte({ typescript: true })`.
- Compiles into Svelte SFCs where store properties become `let` bindings and getters become reactive declarations (`$: getter = ...`).
- In preview builds, TypeScript in Svelte `<script lang="ts">` is preprocessed via `esbuild` before passing to `svelte/compiler`.

### Key Pitfalls & Best Practices

1. **Computed Getter Timing**: Svelte reactive statements (`$:`) evaluate in topological order after microtasks. Avoid mutual dependencies between getters that could cause cycle errors.
2. **Boolean Attributes**: In Mitosis, pass boolean attributes as booleans (`disabled={props.disabled}`) rather than strings to prevent Svelte or Vue 2 from rendering `disabled="false"`.
3. **SVG Attribute Casing**: Always use camelCase for SVG attributes in `.lite.tsx` (`strokeWidth`, `strokeLinecap`, `viewBox`). Mitosis handles framework-specific casing during compilation.
4. **Avoid Global State Pollution**: Keep state scoped to each component instance via `useStore`.
